# Предсказание сердечных заболеваний — MLOps Pipeline

## Model Card:
### Цель модели
Бинарная классификация для прогнозирования наличия сердечного заболевания по медицинским признакам пациента.
Модель является частью учебного MLOps-пайплайна и используется для демонстрации обучения, выбора, регистрации и сервинга ML-модели через MLflow + FastAPI + Docker.
### Метрики
Основная метрика выбора модели: F1-score.
Дополнительно отслеживаются:
* Accuracy
* Precision
* Recall
* ROC-AUC

Лучшая модель автоматически регистрируется в MLflow Model Registry.
### Ограничения
* Модель обучена на датасете UCI Heart Disease и может плохо обобщаться на другие популяции.
* Результаты на тестовом датасете не гарантируют такую же точность на реальных пациентах.
* Модель не является клинически валидированной системой диагностики.
* Предсказания не должны использоваться для постановки диагноза или принятия медицинских решений без участия квалифицированного специалиста.
* Модель учитывает только признаки, представленные в датасете.
### Bias / Fairness анализ
Возможны различия в качестве предсказаний для разных демографических и клинических групп из-за ограниченной репрезентативности обучающего датасета.

В текущей версии проекта отдельный количественный анализ Fairness не реализован. Для production-использования рекомендуется оценивать метрики отдельно для различных групп пациентов.
### Версия данных
**Dataset**: UCI Heart Disease

**Файл**: `data/heart.csv`

**Признаки**: `age`, `sex`, `cp`, `trestbps`, `chol`, `fbs`, `restecg`, `thalach`, `exang`, `oldpeak`, `slope`, `ca`, `thal`

**Target**: `target` - наличие/отсутствие сердечного заболевания (`0/1`).

---
> **Учебный проект по MLOps** Основная цель проекта - изучить и отработать ключевые концепции MLOps путем создания полного ML-конвейера: от обучения модели до её использования в production. Датасет сердечных заболеваний здесь является лишь инструментом для обучения: главное - понять, как **Docker**, **MLflow** и **FastAPI** взаимодействуют в реальном ML-процессе.

## Что охватывает проект

**Docker и Docker Compose**

* Контейнеризация нескольких независимых Python-сервисов, каждый из которых имеет собственный `Dockerfile`
* Оркестрация сервисов с учетом порядка их запуска и зависимостей (`healthchecks`, `depends_on`, `condition: service_completed_successfully`)
* Использование общих volumes между контейнерами для сохранения артефактов MLflow

**MLflow**

* Развертывание MLflow Tracking Server как отдельного сервиса
* Логирование экспериментов: параметров, метрик и сериализованных моделей
* Использование **Model Registry** для версионирования и продвижения лучшей модели
* Загрузка зарегистрированной модели из другого сервиса через её URI (`models:/name/version`)

**FastAPI**

* Создание REST API для предоставления ML-модели с валидацией входных данных через Pydantic
* Управление жизненным циклом модели: загрузка при запуске и освобождение ресурсов при завершении работы с помощью `lifespan`
* Предоставление эндпоинтов `/health` и `/predict`, готовых для реального развертывания

**Порядок запуска** — контролируется с помощью healthcheck в Docker Compose:

1. **MLflow** запускается первым и должен успешно пройти проверку состояния, прежде чем будут запущены остальные сервисы.
2. **Скрипт обучения** запускается после того, как MLflow становится доступен — он обучает все модели, сохраняет результаты в MLflow и регистрирует лучшую модель.
3. **FastAPI** запускается только после того, как MLflow успешно прошел проверку состояния **и** скрипт обучения завершился успешно. После этого FastAPI загружает зарегистрированную модель и начинает обрабатывать предсказания.

## Обучаемые модели

Pipeline обучает следующие классификаторы параллельно, а результаты работы всех моделей отслеживаются в MLflow:

| **Модель**          | **Стратегия предварительной обработки** |
| ------------------- | --------------------------------------- |
| Decision Tree       | Ordinal Encoding, без масштабирования   |
| Random Forest       | Ordinal Encoding, без масштабирования   |
| Gradient Boosting   | Ordinal Encoding, без масштабирования   |
| XGBoost             | Ordinal Encoding, без масштабирования   |
| Logistic Regression | One-Hot Encoding + StandardScaler       |
| SVM (RBF kernel)    | One-Hot Encoding + StandardScaler       |
| K-Nearest Neighbors | One-Hot Encoding + StandardScaler       |
| MLP Neural Network  | One-Hot Encoding + StandardScaler       |

Лучшая модель, определяемая по **F1-score**, автоматически регистрируется в MLflow Model Registry под именем:

```text
heart_disease_prediction
```

## Начало работы

### Требования

* [Docker](https://www.docker.com/) и Docker Compose

### Запуск полного pipeline

```bash
docker compose up --build
```

Эта единственная команда:

* запускает MLflow Tracking Server на `http://localhost:5000`;
* обучает все модели и сохраняет результаты в MLflow;
* регистрирует лучшую модель;
* запускает API для предсказаний на `http://localhost:8000`.

## Использование API

### Проверка состояния сервиса

```bash
curl http://localhost:8000/health
```

### Предсказание сердечного заболевания

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 55,
    "sex": 1,
    "cp": 0,
    "trestbps": 160,
    "chol": 289,
    "fbs": 0,
    "restecg": 0,
    "thalach": 145,
    "exang": 1,
    "oldpeak": 0.8,
    "slope": 1,
    "ca": 1,
    "thal": 3
  }'
```

**Ответ:**

```text
{"prediction": 1}
```

`0` = сердечного заболевания нет
`1` = сердечное заболевание есть

## Конфигурация

В файле `scripts/config.yaml` можно добавлять модели, изменять гиперпараметры или переименовывать эксперимент:

```yaml
name_experiment: heart_disease_prediction

model:
  RandomForestClassifier_v1:
    model_name: 'RandomForestClassifier'
    preproc_strategy: 'tree'
    hyperparameters:
      n_estimators: 100
      max_depth: 5
  # здесь можно добавить другие модели...
```
